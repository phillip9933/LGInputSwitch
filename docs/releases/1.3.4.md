LG Input Switch **1.3.4** improves LG 40U990A-W Thunderbolt detection, adds native
Windows dock discovery and standard DDC/CI switching, fixes configuration/update
recovery, and retires the original Windows frontend.

## Monitor compatibility

- **LG 40U990A-W:** automatic setup now recognizes the `U990A` capabilities alias
  and LG EDID manufacturer/product `GSM / 0x9EBA`, even when the display name is
  only `LG ULTRAFINE`. Thunderbolt uses `0xD2`; USB-C remains `0xD1`. Existing
  manual mappings are preserved. Use **Refresh**, review the detected inputs, then
  **Save settings**. Confirmation on the reporter's unit is still needed.
- **Windows docks:** discovery now includes native Windows monitor connections,
  including DisplayLink routes outside AMD's API. Compatible monitors can use
  **Standard DDC/CI (0x60)** with their standard input values. This path does not
  require an AMD GPU or another bundled runtime library.
- **Important LG limitation:** native Windows DDC/CI cannot specify LG's custom
  source address. It does not implement LG alternate `0xF4`/source-`0x50` switching
  through DisplayLink. The Dell dock report in
  [#5](https://github.com/phillip9933/LGInputSwitch/issues/5) remains unverified.
  Standard switching can be tested explicitly; the app never silently substitutes
  it for an LG alternate command. Existing AMD-driven connections retain raw access.
- Diagnostics add the selected connection type, Windows display, adapter
  association, EDID manufacturer/product and automatic-input mode. Raw EDID,
  serial numbers and local identity hashes remain excluded.

## Reliability and cleanup

- Unreadable/newer settings always open the recovery window, including at sign-in;
  switching and saving stay blocked to preserve the original file.
- Failed update checks retry without waiting a full day. Verified downloads stay
  ready to install, and slow downloads use an inactivity timeout instead of a
  three-minute total limit. Host, size and SHA256 verification remain enforced.
- Temporarily missing monitor inputs recover their action mappings, names and
  shortcuts when the original input codes return, including after saving/restarting.
  Manual disabling and shortcut conflicts are respected across monitor groups.
- Backend discovery errors are retained, and stderr warnings no longer contaminate
  machine-readable capability output.
- Global shortcuts reject plain typing keys; Windows navigation keys are supported.
  Old shortcut settings remain readable for repair.
- The retired Win32 tray/dialog frontend, Visual Studio project, duplicate settings
  writers and legacy build artifact are removed. Old Windows config.json and
  pre-profile Qt settings still import through a read-only Qt JSON module.
- CMake, Linux qmake entry points and Arch package build dependencies are updated.

## Downloads and upgrade

- **Windows x64:** `LGInputSwitch-1.3.4-Windows-x64.exe` — one portable executable;
  no installer, Qt DLL folder or separate runtime setup.
- **CachyOS/Arch:** `lginputswitch-1.3.4-1-x86_64.pkg.tar.zst`.
- **SHA256SUMS:** checksums for both binaries. GitHub supplies source ZIP/tar.gz
  downloads automatically. No legacy or auxiliary assets are uploaded.

Use **Preferences → Application updates**, or quit the app and update manually.
Back up settings first. On Windows, replace the executable in its existing writable
folder, retaining its filename and configuration files. Review/save automatic
input changes separately after upgrading. Configurations with native Windows
routes or pending input recovery use schema 4; older apps reject that schema, so
keep your settings backup if you need to roll back.
